INLAND DEEP CONSOLE

Navigating the Inland Deep: Adaptive Sensor Fusion and Homing Intelligence for Autonomous Underwater Systems

  • Domain: Autonomous Underwater Robotics • Distributed Big Data Telemetry • Cyber-Physical Control Systems
  • Core Technologies: Apache Spark 3.5 • Scala 2.13 • Apache Pekko HTTP • React 18 & Three.js WebGL

SPEAKER NOTES: Welcome the committee and introduce Inland Deep Console: a platform combining an optical turbidity-adaptive Kalman filter with Apache Spark big data analytics to deliver high-reliability navigation for low-cost autonomous underwater vehicles in GPS-denied inland waters.
SLIDE 02 / ABSTRACT

Executive Summary & Abstract

  • Problem: GPS signal attenuation in freshwater bodies, sensor distortion caused by benthic sediment plumes, and budget limits barring expensive DVL arrays.
  • Proposed Thesis: Turbidity-Adaptive Kalman Filter (AKF) modulating measurement covariance $R_k$ dynamically as a function of optical Nephelometric Turbidity Units (NTU).
  • Big Data Architecture: Apache Spark 3.5 streaming pipeline executing 10-second micro-windowed aggregations, data cleansing, and Spark SQL batch queries over Parquet data lakes.
  • Autonomous Safety: Closed-loop Homing State Machine (FSM) enabling autonomous return-to-base docking upon battery depletion (<20%) or acoustic link failure.
  • Demonstrated Result: 35% to 52% reduction in overall trajectory Root Mean Square Error (RMSE) over fixed-gain baselines.
SLIDE 03 / PROBLEM STATEMENT

The Inland Underwater Navigation Dilemma

  • Complete GPS Denial: High-frequency RF signals attenuate within millimeters of freshwater entry, depriving submersibles of external geospatial position coordinates.
  • Prohibitive Sonar/DVL Costs: Commercial Doppler Velocity Logs (DVL) and multibeam sonar suites cost between $25,000 and $100,000—making budget micro-AUVs inaccessible.
  • Quadratic Dead Reckoning Drift: Inertial Measurement Units (IMUs) suffer continuous bias and noise, leading to quadratically compounding positioning error over time ($e \propto t^2$).
  • Sediment Plume Corruption: Thruster wash and bottom thermoclines stir dense silt plumes (>100 NTU), inducing severe high-frequency jitter in acoustic and pressure depth sensors.
SLIDE 04 / OBJECTIVES

Project Objectives

  • 1. Formulate Turbidity-Adaptive Filter: Develop an Extended Kalman Filter that dynamically redistributes trust between kinematics and sensors using real-time optical backscatter.
  • 2. Build Distributed Telemetry Pipeline: Implement an Apache Spark 3.5 streaming processor with 10-second window aggregations and Snappy-compressed Parquet batch storage.
  • 3. Design Autonomous Fail-Safe FSM: Construct a deterministic finite state machine handling automated return-to-base transit and precision docking latching.
  • 4. Engineer Digital Twin Cockpit: Create a full WebGL 3D vehicle attitude tracker with living water turbidity shaders and ghost path sonar maps.
  • 5. Benchmark & Validate: Statistically quantify error reduction across clear, silt, and sediment storm conditions.

SLIDE 07 / SYSTEM ARCHITECTURE

End-to-End System Architecture

  • Edge Sensing Layer: ESP32 microcontroller reading MPU6050 IMU, MS5837 pressure depth, and optical NTU probe.
  • Pekko HTTP Actor Server: Ingests 5 Hz telemetry via REST/WebSocket, orchestrating state pipelines with sub-millisecond latency.
  • Filtering & Estimation Bank: Dual filters (Fixed vs Adaptive) compute 9-state kinematic estimates concurrently with ground truth.
  • Spark Big Data Engine: Ingests sliding frames, executes data cleaning, computes 10-second tumbling aggregations, and writes Parquet partitions.
  • Web Cockpit Dashboard: Three.js 3D kinematics, Living Water canvas, Ghost Path sonar map, and Spark PDF reporting modal.
SLIDE 08 / METHODOLOGY

Methodology & Workflow

  • Phase 1 (Ingestion): Capture 5 Hz telemetry; validate data bounds (depth: 0-150m, battery: 0-100%, non-NaN accelerations).
  • Phase 2 (Coordinate Transform): Transform body-frame accelerations into earth-frame reference using Euler rotation matrices with gravity cancellation.
  • Phase 3 (Adaptive Filtering): Compute NTU scaling factor; scale measurement covariance $R_k$; update state vector with innovation residuals.
  • Phase 4 (Big Data Streaming): Spark Structured Streaming consumes telemetry buffer; aggregates mean NTU, depth variance, and min battery.
  • Phase 5 (Homing Evaluation): Check safety triggers; calculate beacon bearing angle and distance vector.
SLIDE 09 / DATASET DESCRIPTION

Dataset Description & Telemetry Schema

  • Telemetry Packet Schema: 12 core sensor attributes streamed at 200 ms intervals:
    { mission_id, ts, depth, ax, ay, az, gx, gy, gz, heading, ntu, battery }
  • MPU6050 IMU: 3-axis acceleration ($\pm 2g$) and 3-axis angular rates ($\pm 250^\circ/\text{s}$).
  • MS5837 Pressure Sensor: Piezoresistive sensor measuring water column hydrostatic pressure down to 150m.
  • Optical NTU Turbidity: Backscatter photodiode measuring suspended sediment particles (0 to 1000 NTU).
  • Parquet Columnar Lake: Partitioned by `mission_id` with Snappy compression for fleet-scale historical query execution.

SLIDE 13 / ALGORITHM LOGIC

Algorithm: Turbidity-Adaptive Kalman Filter

  • Step 1: Turbidity Noise Scaling Function:
    noise_scale = 1.0 (NTU < 20) | 2.5 (20 <= NTU < 100) | 5.0 (NTU >= 100)
  • Step 2: Measurement Covariance Expansion:
    R_k = R_0 * noise_scale(NTU)
  • Step 3: Kalman Gain Attenuation:
    K_k = P * H^T * (H * P * H^T + R_k)^(-1)
  • Outcome: In dense silt clouds, $R_k$ expands up to 5x, shrinking $K_k \rightarrow 0$. The filter rejects transient depth and acceleration spikes, relying on hydrodynamic prediction until water clears.

SLIDE 17 / CHALLENGES & SOLUTIONS

Challenges Faced and Solutions

  • Spark Streaming Latency: Tumbling windows created latency on local threads $\rightarrow$ Decoupled real-time 5 Hz WebSocket flow from 10-second batch aggregations with tuned partitions (`partitions = 2`).
  • Sensor Lag during Turbidity Surges: Fixed filters over-reacted to corrupted depth readings $\rightarrow$ Scaled measurement noise $R_k$ up to 5x to command the filter to rely on drag-damped kinematics.
  • Heading Discontinuity at 360°: Yaw angle subtraction caused wrap-around jumps $\rightarrow$ Implemented trigonometric circular error wrapping: `atan2(sin(Δθ), cos(Δθ))`.
  • WebSocket Browser Memory Bloat: Extended missions accumulated thousands of frames $\rightarrow$ Implemented FIFO circular buffer capping active history to 400 frames.
